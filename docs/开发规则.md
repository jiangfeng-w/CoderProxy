## 构建与打包（操作手册）

> 底料/原理见 `docs/spec/M5-打包与分发/M5-打包与分发.md`。以下为照做步骤；产物路径均相对仓库根。

> ⚠ **打包后不要自动安装**（2026-09-06 用户明确）：安装会杀运行中的应用、中断正在进行的对话（agent 经本 relay 出模型）。只产出安装包并告知路径，安装时机由用户自己掌握。

**完整序（改过 relay/前端/壳任一处后）**

```bash
# 1) sidecar：PyInstaller onefile + 拷为 src-tauri/binaries/relay-sidecar-x86_64-pc-windows-msvc.exe
#    ⚠ 解释器必须用本机可用的 Python 3.13（`py -3.13`：带 pip、会读 PYTHONPATH）。
#       不要用 `python` 指向的 shim（3.12 Codex）——它无 pip、无 PyInstaller、不读 PYTHONPATH，
#       `python relay/build_sidecar.py` 会报「No module named PyInstaller/pip」。
#    步骤：先把 relay/_deps 注入 PYTHONPATH，再从仓库根跑（构建脚本用 sys.executable 起 -m PyInstaller）。
#    PowerShell（本机实测）：
$env:PYTHONPATH="$PWD\relay\_deps"
py -3.13 relay/build_sidecar.py
#    bash：
#    export PYTHONPATH="$PWD/relay/_deps" && py -3.13 relay/build_sidecar.py
#    （等价：在 relay/ 下执行 $env:PYTHONPATH="$PWD\_deps"; py -3.13 build_sidecar.py）

# 2) 前端 build + 类型检查（Tauri beforeBuildCommand 会自动跑 npm run build，含构建）

# 3) 出安装包（NSIS，中英双语）：自动集成 sidecar + 前端产物
#    须在仓库根执行；tauri CLI 未全局装，走 frontend 的本地 CLI + --config 指到 src-tauri
.\frontend\node_modules\.bin\tauri.cmd build --bundles nsis --config .\src-tauri\tauri.conf.json
```

**产物**

| 产物          | 路径                                                                       | 说明             |
| ----------- | ------------------------------------------------------------------------ | -------------- |
| NSIS 安装包    | `src-tauri/target/release/bundle/nsis/CoderProxy_0.1.0_x64-setup.exe`    | 交付版            |
| 便携 zip      | `src-tauri/target/release/bundle/portable/CoderProxy_0.1.0_portable.zip` | 手动组装（见下）       |
| 主程序 exe     | `src-tauri/target/release/coderproxy-desktop.exe`                        | release 壳      |
| sidecar exe | `src-tauri/binaries/relay-sidecar-x86_64-pc-windows-msvc.exe`            | PyInstaller 产物 |

**便携包（手动 zip，Tauri 不支持 portable target）**

```powershell
$d = "src-tauri\target\release\bundle\portable"
Remove-Item -Recurse -Force "$d\CoderProxy_0.1.0_portable", "$d\CoderProxy_0.1.0_portable.zip" -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Path "$d\CoderProxy_0.1.0_portable" -Force | Out-Null
Copy-Item "src-tauri\target\release\coderproxy-desktop.exe" "$d\CoderProxy_0.1.0_portable\coderproxy-desktop.exe"
Copy-Item "src-tauri\binaries\relay-sidecar-x86_64-pc-windows-msvc.exe" "$d\CoderProxy_0.1.0_portable\relay-sidecar.exe"
Push-Location $d; Compress-Archive -Path "CoderProxy_0.1.0_portable" -DestinationPath "CoderProxy_0.1.0_portable.zip" -Force; Pop-Location
```

**关键点**

- data 目录自动解析：安装版/便携版数据都优先落 **exe 旁** **`data/`**，无写权限（如 Program Files）回退 `%APPDATA%`；首次切换自动迁移旧 `relay_state.json`。见 `lib.rs::resolve_data_dir/migrate_legacy_data`。

- 便携 exe **依赖系统 WebView2**（Win11 预装，Win10 需自带）。

- sidecar 是 twofile bootloader+relay 两层，进程树回收走 Job Object（`lib.rs`）；打出的 install 需真机验证进程不残留。

## 对接指针（给实现 agent 的关键位置）

- 登录状态机：`relay/app/auth/ta3/oauth.py`（`start_login`/`get_login_status`/`cancel_login`；先 IM 静默后 PKCE-SM3）。

- 请求伪装内核：`relay/app/models/providers/ta3.py` 的 `Ta3Provider.stream_structured`（头 + 工具名双向 + SSE 解析）。

- 工具名表：`ta3_tool_aliases.py` 的 `TO_TA3/FROM_TA3/ARGS_TO_TA3/ARGS_FROM_TA3`；schema 见 `ta3_tool_schemas.py` 的 `TA3_NATIVE_SCHEMAS`。

- 出站 OpenAI SSE 组装：`relay/relay/oai_adapter.py`（思考→`reasoning_content`，结尾 `usage`+`finish_reason`+`[DONE]`）。

- 竞品指纹净化：`relay/relay/oai_adapter.py` 的 `_sanitize_fingerprint`（上游风控按竞品身份句精确子串封禁，品牌词插 ZWSP 绕过；黑名单扩充改 `_FINGERPRINT_BRAND_RE`，实测证据见 `docs/上游风控与客户端兼容.md`）。

- 上游错误透传：`relay/relay/routes.py` 的 `_extract_upstream_error`/`_upstream_error_response`（ta3.py 的 RuntimeError 文本解析出状态码，非流式/流式首帧前透传，流中途补错误帧；流式预拉首帧是透传的前提，改 gen() 结构时别破坏）。

- 自举/环境坑：见 `docs/README.md`「自举环境」。

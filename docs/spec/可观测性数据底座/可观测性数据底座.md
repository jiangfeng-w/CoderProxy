> **状态**：方案已定稿（2026-10-17；用户拍板：**事件流 + 请求汇总表** / **原始 message+body 截断脱敏** / 统计第一版 **Token+性能+成功率**）
> **优先级**：核心（日志页重构、统计页重构的共同前置）
> **来源**：2026-10-17 日志与统计需求重评估。用户要求：保留服务端原始错误、拆日志列、扩展可展示字段、统计多维化；参考 cc-switch / sub2api 的统计部分（仅统计）。
> **依赖**：M6 数据底座、M8 `/v1/stats`、原《[统计-TTFB与吐字速率](../统计-TTFB与吐字速率/统计-TTFB与吐字速率.md)》（**并入本需求**）
> **定稿日期**：2026-10-17

## 1. 背景与目标

### 背景

现状是「事件流水账 + `detail` JSON 口袋」：

- `logs` 只有 11 个独立列；`chat_request` 的 tools/thinking/protocol、`chat_error` 的 error/raw_tail、`wb_pick` 的 uid/nickname/priority 全塞在 `detail`，无法筛选/聚合。
- 上游原始错误在 adapter 层被转换后，`routes` 只落 `str(exc)[:500]`：WorkBuddy 的 `raw_msg`、`displayTips`、原始 body，自定义供应商的原始 body，均被丢弃；牛码的原始 body 也只是裹在 RuntimeError 字符串里截断。
- `duration_ms` 只有 `chat_done` 有；`chat_error` 没有耗时；没有 TTFB、tok/s、`finish_reason`、上游状态码/业务码。
- `/v1/stats` 的 `requests = COUNT(*)` 把 `chat_request`、`chat_done`、`chat_error`、`wb_pick`、`auth_401_refresh` 全算成请求，成功率被稀释；这是本轮必须一起修的口径问题。
- 原《统计-TTFB与吐字速率》已定稿但未实现；统计页重做需要这些字段，故并入本需求，避免做两遍。

### 目标

| # | 功能 | 说明 |
|---|---|---|
| F1 | 请求级关联 | 每次 `/v1` 聊天请求生成 `request_id`，贯穿 `chat_request` / `wb_pick` / `auth_401_refresh` / `chat_done` / `chat_error` |
| F2 | 请求汇总表 | 新增 `requests`（一请求一行），承担日志列表与统计口径；`logs` 保留事件明细 |
| F3 | 结构化字段 | 把可筛选/可聚合字段升级为独立列（provider/protocol/endpoint/account/status/error_kind/finish_reason/TTFB/tok/s 等） |
| F4 | 原始错误双轨 | 同时保留「面向 agent 的转换后消息」与「上游原始 message/body/status/code/displayTips」，body 截断 + 脱敏 |
| F5 | 性能观测 | 流式首 token 等待 `first_token_ms`、吐字速率 `tokens_per_second`、`finish_reason`、响应字符数/工具调用数 |
| F6 | 查询 API | `/v1/requests` 列表/详情、`/v1/logs` 扩展筛选、facets、按条件清空 |
| F7 | 兼容与迁移 | `logs` 走既有自省补列；旧行 `request_id` 为空；新统计只覆盖升级后请求；旧接口保留兼容 |
| F8 | 测试 | keyless 单测覆盖生命周期、错误捕获、TTFB 公式、脱敏、迁移、清空级联 |

### 非目标

- ❌ 不保存成功请求的完整请求体/响应正文（隐私与库体风险）；只保存**错误请求**的上游原始响应体。
- ❌ 不做成本/价格、配额/余额、账单（订阅账号下单请求金额无稳定语义；后续单独立项）。
- ❌ 不做日志页/统计页 UI（见《[日志页重构](../日志页重构/日志页重构.md)》《[统计页重构](../统计页重构/统计页重构.md)》）。
- ❌ 不改变 agent 侧 OpenAI/Responses/Anthropic 协议语义。
- ❌ 不做主动健康巡检（仍归《真实请求反哺模型状态》）。

## 2. 数据模型

索引：

- `idx_logs_request_id(request_id)`
- `idx_logs_kind_ts(kind, ts)`
- `idx_logs_provider_ts(provider, ts)`

> `detail` 继续承载长尾：错误原始体、上游响应头、工具名列表、请求参数快照等。**任何要参与 WHERE/GROUP BY 的字段必须建独立列**（M6/M8 既有约束）。

| `model_requested` | TEXT | agent 请求的完整模型名（含前缀） |
| `model_bare` | TEXT | 去掉供应商前缀后的模型名 |
| `model_upstream` | TEXT | 上游实际模型名（可空） |
| `provider` | TEXT | 同上 |
| `protocol` | TEXT | 同上 |
| `endpoint` | TEXT | 同上 |
| `stream` | INTEGER | 0/1 |
| `account_uid` | TEXT | 最后一次选中的账号 |
| `http_status` | INTEGER | 上游 HTTP 状态 |
| `upstream_code` | TEXT | 上游业务码 |
| `error_kind` | TEXT | 错误分类；成功为 NULL |
| `error_stage` | TEXT | 错误阶段 |
| `retryable` | INTEGER | 0/1；错误是否可重试 |
| `error_message` | TEXT | **转换后**、面向 agent 的错误消息 |
| `error_log_id` | INTEGER | 指向 `logs.id`（该请求的终态错误事件） |
| `finish_reason` | TEXT | 上游结束原因 |
| `prompt_tokens` | INTEGER | usage |
| `completion_tokens` | INTEGER | usage |
| `cached_tokens` | INTEGER | usage |
| `reasoning_tokens` | INTEGER | usage |
| `total_tokens` | INTEGER | usage |
| `duration_ms` | INTEGER | 请求入口 → 上游完成 |
| `first_token_ms` | INTEGER | 流式首 token 等待 |
| `tokens_per_second` | REAL | 见 §4 |
| `retry_count` | INTEGER | 默认 0 |
| `switch_count` | INTEGER | 默认 0 |
| `tool_mode` | TEXT | 牛码链路工具模式 |
| `thinking_effort` | TEXT | 最终思考档位 |
| `tool_count` | INTEGER | 入站工具数 |
| `message_count` | INTEGER | 入站消息数 |
| `has_tools` | INTEGER | 0/1 |
| `has_images` | INTEGER | 0/1 |
| `is_probe` | INTEGER | 0/1（GUI 连通性探针） |
| `client_agent` | TEXT | 归一后的 agent 名 |
| `user_agent` | TEXT | 原始 UA（截断 512） |
| `client_ip` | TEXT | 入站 IP（本机通常 127.0.0.1） |
| `detail` | TEXT | JSON：请求参数快照、缓存命中率等派生值 |

索引：

- `idx_requests_started_at(started_at)`
- `idx_requests_provider_started(provider, started_at)`
- `idx_requests_model_started(model_requested, started_at)`
- `idx_requests_status_started(status, started_at)`
- `idx_requests_error_kind(error_kind)`
- `idx_requests_account(account_uid)`

**状态生命周期**：

1. `_handle_chat` 收到请求 → 生成 `request_id`，插入 `requests(status='in_progress')`，写 `chat_request` 事件。
2. 每次选号/换号 → 写 `wb_pick` 事件（带 `request_id`），更新 `requests.account_uid` / `switch_count`。
3. 401 刷新 → 写 `auth_401_refresh` 事件，更新 `retry_count`。
4. 成功 → 更新 `requests(status='success')`，写 `chat_done`。
5. 失败 → 更新 `requests(status='error')`，写 `chat_error`（`error_log_id` 指向该行），原始体在该行 `detail`。
6. 进程异常退出 → 启动时把超过 10 分钟仍 `in_progress` 的行标记为 `interrupted`（不伪造耗时/token）。

### 2.3 字段归属原则

| 归属 | 字段 |
|---|---|
| **独立列**（筛选/聚合/排序） | request_id、provider、protocol、endpoint、model_requested/model_bare/model_upstream、account_uid、status/http_status/upstream_code/error_kind/error_stage、finish_reason、stream、tokens、duration_ms、first_token_ms、tokens_per_second、retry_count、switch_count、tool_mode、thinking_effort、client_agent、is_probe |
| **`detail` JSON**（长尾/大字段） | 上游原始 body、上游响应头、displayTips、工具名列表、请求参数快照、错误 raw_tail、其他不稳定扩展 |
| **不落** | 成功请求正文、完整 messages、图片 base64、token/密钥 |

### 2.4 可获取字段清单（实现依据）

#### A. 已落库（现状）

`ts` / `kind` / `model` / `stream` / `prompt_tokens` / `completion_tokens` / `cached_tokens` / `reasoning_tokens` / `total_tokens` / `duration_ms` / `detail`。

#### B. 请求入口层可拿（本轮接线）

- 标识：`request_id`（生成）、`endpoint`、`parse_protocol`/`response_protocol`、`client_ip`、`user_agent`、入站 `x-request-id`。
- 路由：`provider`/前缀、`model_requested`、`model_bare`、`model_upstream`、`probe`。
- 参数：`stream`、`temperature`、`max_tokens`、`tool_choice`、`response_format`、`metadata/user`、`message_count`、角色分布、`has_system`、`has_images`、`tool_count`、工具名。
- 思考/工具：`thinking`、`thinking_effort`、`tool_mode`、`map_hits`、`longtail_passthrough`、`dropped`。
- 账号：`account_uid`、`nickname`、`priority`、`pool_size`、`attempt_index`、`pick_reason`（优先级/轮询/跳过停用/跳过冷却）。
- 刷新/重试：401 刷新 attempt/status、`retry_count`、`switch_count`。

#### C. 上游响应层可拿（本轮接线）

- 响应：`http_status`、`upstream_code`、`raw_msg`、`raw_body`、`displayTips`、`upstream_request_id`/`trace_id`、响应头（`Retry-After` 等）。
- 完成：`finish_reason`、`model_returned`、`response_id`、usage 明细。
- 性能：`first_token_ms`、`tokens_per_second`、`content_chars`、`reasoning_chars`、`tool_calls_count`、`stream_frame_count`。
- 错误：`error_kind`、`error_stage`、`retryable`、`attempt_count`、`switched_account`、`fallback_to_stream`、`empty_stream_raw_tail`。

#### D. 拿不到 / 后续单独立项

- 成本/价格：需要模型价格表；订阅账号下单请求金额无稳定语义。
- 配额/余额：平台侧账号快照，不是单请求精确值。
- 上游排队时间：只能拿到总 TTFB，拆不出排队 vs prefill。
- 精确 tokenizer 计数：只能信上游 usage。
- 完整成功请求/响应正文：默认不存；如需排障可加临时 debug 开关（另议）。
- 上游堆栈：上游不暴露。
- 按 agent 的独立身份：当前只有一个 `RELAY_API_KEY`，只能靠 UA/endpoint 归一。

### 2.5 错误分类

`error_kind` 取值：

| kind | 含义 |
|---|---|
| `auth` | 401/403、凭证失效、登录态失效 |
| `rate_limit` | 429/6004、频率限制、额度/限流 |
| `model_missing` | 11102、模型不存在/不可用 |
| `session` | 11140 request illegal（非限流文案）、12153 会话失效 |
| `content` | 内容审核/策略拦截/上下文超长等 4xx 内容类 |
| `business` | 其他 4xx 业务错误 |
| `network` | DNS/连接失败/断连 |
| `timeout` | 读超时/上游停滞 |
| `upstream_5xx` | 上游 5xx |
| `empty_stream` | 空响应重试耗尽 |
| `parse` | 响应/协议解析失败 |
| `local_rejected` | relay 本地白名单/模型校验拒绝 |
| `unknown` | 无法归类 |

`error_stage`：`request_parse` / `model_check` / `pre_stream` / `mid_stream` / `non_stream`。

## 3. 写入链路与错误捕获

### 3.1 请求入口

`relay/relay/routes.py::_handle_chat`：

- 生成 `request_id = "req_" + uuid4().hex`。
- 构建请求上下文（endpoint、protocol、provider、model、stream、client_ip、user_agent、client_agent、probe、tool_mode、thinking_effort、message_count、tool_count、has_tools、has_images）。
- 插入 `requests(in_progress)` + `chat_request` 日志。
- 把 `request_id` 传给后续日志点。

### 3.2 事件日志

- `wb_pick`：由 `platforms/workbuddy/chat.py::_log_pick` 增加 `request_id`、`attempt_index`、`pick_reason`；同步更新 `requests.account_uid` / `switch_count`。
- `auth_401_refresh`：增加 `request_id`、`attempt`、`status`；同步更新 `retry_count`。
- `chat_done`：写 usage、duration、TTFB、tok/s、finish_reason、model_upstream、tool_calls_count、content_chars、reasoning_chars；更新 `requests(success)`。
- `chat_error`：写 `error_kind`/`error_stage`/`http_status`/`upstream_code`/`error_message` + `detail.upstream_raw_*`；更新 `requests(error)` 并回填 `error_log_id`。

### 3.3 原始错误双轨

统一错误信息对象（建议 dataclass）：

```
UpstreamErrorInfo:
  http_status: int | None
  upstream_code: str | None
  raw_msg: str | None
  raw_body: str | None
  display_tips: str | None
  upstream_request_id: str | None
  error_kind: str
  error_stage: str
  retryable: bool
```

各链路接线：

- **牛码 `ta3.py`**：`_extract_upstream_error` 已能拆出 `(status, text)`；`text` 作为 `raw_body`，不再只拼进字符串。
- **WorkBuddy `parse_error`**：保留 `raw_msg`、`raw_body=body_text`、`displayTips`（解析 `displayTips`/`display_tips` 字段）、`http_status`、`code`；`_UpstreamCodeError` 增加对应属性。
- **自定义供应商 `custom_openai.py`**：`UpstreamHttpError` 增加 `raw_body`/`raw_msg`；`_error_text` 只负责生成面向 agent 的消息，不再丢弃原文。
- **流中途错误**：`_stream_once` 的 `__error__` 帧带 `(status, text)`；把 `text` 作为 `raw_body`。
- **空响应**：保留既有 `raw_tail`（最多 8 行、每行 300 字）到 `detail.upstream_raw_tail`。

### 3.4 截断与脱敏

- `raw_body` 上限 **8192 字节**（UTF-8），超出截断并置 `raw_body_truncated=true`；保留原始字节数 `raw_body_bytes`。
- 脱敏规则（大小写不敏感）：
  - `Authorization: Bearer ...` → `Authorization: Bearer ***`
  - `x-api-key` / `api-key` / `x-goog-api-key` → `***`
  - `Cookie` / `Set-Cookie` → `***`
  - JWT（三段 base64url）→ `***`
  - `sk-...` / `$wbEncrypted` 值 → `***`
- 只对 `chat_error` 保存原始体；成功响应不保存正文。

## 4. TTFB 与吐字速率

### 4.1 采集

扩展 `oai_adapter.UsageCollector`：

- `mark_first_token()`：首个**非空** `content` 或 `reasoning_content` delta 时打点（role 帧、零值 delta 不算）。
- `record(usage, finish_reason=...)`：done 时记录 usage、finish_reason、content_chars、reasoning_chars、tool_calls_count、stream_frame_count。
- `first_token_ms = int((first_token_at - started) * 1000)`；无首 token → NULL。
- `duration_ms` 口径不变（请求入口 → 上游 done；不含 SSE 下行至 agent）。

### 4.2 公式

```
tps = completion_tokens * 1000 / (duration_ms - first_token_ms)
```

- `first_token_ms` 缺失 / ≤0 → 分母回落到 `duration_ms`；
- `duration_ms - first_token_ms < 200ms` → 回落到 `duration_ms`（假流式幻数防护）；
- `completion_tokens <= 0` 或 `duration_ms <= 0` → 不产出 tps；
- 非流式：不产出 TTFB；tps 可选按 `completion_tokens*1000/duration_ms`（仅当 duration>0）。

## 5. API

### 5.1 `GET /v1/requests`

分页请求汇总列表。

参数：`limit`（默认 50，最大 200）、`offset`、`time_from`、`time_to`、`status`、`model`、`provider`、`protocol`、`endpoint`、`account_uid`、`error_kind`、`stream`、`request_id`、`q`（在 `error_message`/`user_agent`/`request_id` 中模糊匹配）、`sort`（`started_at` / `duration_ms` / `first_token_ms` / `tokens_per_second` / `total_tokens` / `status`，默认 `started_at`）、`order`（`asc` / `desc`，默认 `desc`）。

返回：

```json
{
  "rows": [ { "request_id": "...", "status": "success", "...": "..." } ],
  "total": 123,
  "facets": {
    "models": [], "providers": [], "protocols": [],
    "statuses": [], "error_kinds": [], "accounts": []
  }
}
```

### 5.2 `GET /v1/requests/{request_id}`

返回 `{ request, events, raw_error }`：

- `request`：`requests` 行；
- `events`：该 `request_id` 的全部 `logs` 行，按 id 升序；
- `raw_error`：终态错误事件的 `detail`（含 `upstream_raw_msg`/`upstream_raw_body`/`raw_body_truncated`/`display_tips`）。

### 5.3 `GET /v1/logs`（扩展）

保留现有参数；新增 `request_id`、`provider`、`protocol`、`status_code`、`error_kind`、`account_uid`、`client_agent`。返回结构不变，新增列随行返回。

### 5.4 `GET /v1/logs/facets`

返回当前过滤条件下的 distinct 值：`models` / `providers` / `protocols` / `statuses` / `error_kinds` / `accounts` / `client_agents`。供日志页/统计页筛选下拉。

### 5.5 `DELETE /v1/requests`

按与列表相同的过滤条件清空；事务内先删关联 `logs`（按 `request_id`），再删 `requests`；返回 `{deleted_requests, deleted_logs}`。无参数 = 全清。

### 5.6 兼容

- 旧 `GET /v1/logs`、`GET /v1/logs/kinds|models`、`DELETE /v1/logs`、`GET /v1/stats` 保留。
- 新前端不再依赖旧 `/v1/stats`；旧接口标记 deprecated，后续版本可移除。

## 6. 迁移与保留

- `logs` 新列走 `db.py::COLUMN_DEFS` 自省补列；旧行新列为 NULL。
- `requests` 建表在 `_ensure_schema` 内幂等创建。
- 旧日志无 `request_id`，不做不可靠回填；日志页「事件视角」仍可查旧数据；新统计只覆盖升级后请求。
- 保留策略：
  - `logs` 继续用 `settings.relay_log_max_rows` 滚动删除；
  - `requests` 新增 `settings.relay_request_max_rows`（默认 100000），按 `started_at` 滚动删除；
  - 删除 `requests` 时级联删除同 `request_id` 的 `logs`，避免孤儿事件。
- 启动时执行 `UPDATE requests SET status='interrupted', finished_at=... WHERE status='in_progress' AND started_at < now-10min`。

## 7. 已知边界 / 风险

- **旧数据不可回填**：升级前日志没有 request_id，新统计从升级后开始；旧事件仍可在事件视角查看。
- **旧事件清理**：`DELETE /v1/requests` 只删除有 `request_id` 的关联事件；升级前无 `request_id` 的旧行需在事件视角用 `DELETE /v1/logs` 清理。
- **原始体大小**：8KB 上限可能截断大错误页；保留 `raw_body_bytes` 与截断标记，UI 明示。
- **脱敏不可能 100%**：按已知敏感键/模式脱敏；仍建议原始体只在本地查看，不做云同步。
- **trace/request id 是 best-effort**：不同上游返回的头不同，拿不到就留空。
- **流式异常**：客户端断开/进程退出时可能只有 `in_progress`；启动 sweep 标记 `interrupted`，不伪造完成数据。
- **SQLite 写放大**：一请求多事件 + 汇总表更新；写操作继续走 `to_thread`，单请求写入次数控制在个位数。
- **缓存命中率口径**：不同供应商 `prompt_tokens` 是否含 cached 不同；统一按「cached / (prompt + cached)」计算，并在 UI tooltip 注明上游口径差异。
- **非流式无 TTFB**：只记 duration；tps 可选按端到端计算。
- **成本/配额不在本期**：后续单独立项。

# 开发需求文档总览

本目录存放 CoderProxy 的全部开发需求文档，**一个需求一个子目录，子目录内一篇需求 + 该期支撑脚本/文档**。需求**按名字命名，不再按序号递增**（临时插入需求不再需要改动其它需求的编号）；进度在下面「需求列表」里跟踪状态。方案细节以根目录 `CoderProxy-开发计划-2026-09-03.md` 为准，本目录只放单篇需求/实现的落地口径。

> 注：① 本项目**无竞品项目分析**（区别于 Bing Rewards 的 `docs/Bing Rewards 赛道竞品分析.md`）。需求来源 = 开发计划的调研结论 + M1 探针实测证据。② 历史需求（M1–M10）沿用 `M<序号>-<名>` 目录名便于追溯；**新需求一律用需求名**建子目录，不编序号。

## 目录约定

```
spec/
├─ README.md                     # 本总览（记录每条需求及状态）
├─ <需求名>/<需求名>.md          # 新需求：按需求名建子目录 + 同名需求文档
├─ M1-登录与网关探针/            # 历史需求（沿用 M 序号目录名，仅作追溯）
├─ M2-中继核心OpenAI兼容API/
├─ M3-工具名双向伪装/
├─ M4-Tauri桌面壳与GUI/
├─ M5-打包与分发/
├─ M6-数据持久化与日志/          数据底座：SQLite 落库 + /v1/logs API + AppData 指针文件（含壳侧 resolve_data_dir 改写）
├─ M7-GUI日志页/                GUI 日志历史浏览（/v1/logs 消费；Rust relay 放行 DELETE）
├─ M8-Token统计页/              /v1/stats 聚合 + 前端统计页
├─ M9-服务开关/                对 agent 的 /v1 服务软停（不动登录/配置/日志底座）+ 登录后自动启动
├─ M10-设置页与侧边栏登录/       数据目录查看/修改（change_data_dir + 迁移 + UI）+ 登录入口移到侧边栏
├─ 分端口-停止真关agent端口/     停止=真关 agent 端口（base 内部口 + agent 对外口）
├─ 连通性测试-白名单豁免/       模型「测试/启用」对未启用模型被白名单 404 拦截的死锁修复（测试请求需真到上游）
├─ 真实请求反哺模型状态/        模型页连通状态用真实请求证据反哺（严格可达性判定）
├─ 配置真值-持久化与Pinia前端状态/  配置落盘+启动装载（持久化优先）+ 前端 Pinia 单一状态 + 壳去配置镜像（修顶栏模式恒显/重置密钥 401/重启丢配置）
├─ 多agent工具指纹采集与映射/  被动采集各 agent 真实工具声明（归一化+落 SQLite）+ 后续语义映射成双向伪装表
└─ 多协议端点兼容-三协议入站统一/  三协议（ChatCompletions/Responses/Anthropic）入站统一为 ChatRequest；含牛码出站协议确认 + ChatRequest 可靠性排查（k3 自动结束）
```

每个子目录：`<需求名>.md`（需求）+ 该期其他文件（脚本/支撑文档，如 mock 脚本直接放同级）。历史需求文件名沿用 `M<序号>-<名>.md`；新需求为 `<需求名>.md`。

## 状态说明

| 状态      | 含义                                     |
| -------- | ---------------------------------------- |
| 规划中    | 需求已明确，实现前需先定稿设计方案                 |
| 方案已定稿 | 设计方案已确认（含向开发计划回填），可直接按文档实现       |
| 开发中    | 已排期、正在实现（用于进行中的需求）               |
| 已实现    | 已落地并在状态栏标注完成日期                   |

> 状态流转：规划中 → 方案已定稿 → 开发中 → 已实现；已实现保留文档作设计记录。

## 演进顺序（历史，仅作追溯）

M1（验证信链 + 定夺工具策略）→ M2 relay（跑通 chat/completions + 鉴权）→ M3 工具伪装（hybrid 接入）→ M4 GUI 壳 → M5 打包 → M6 数据底座 → M7 GUI 日志页 → M8 Token 统计 → M9 服务开关 → M10 设置页与侧边栏登录。M2 是纯后端核心，先稳它；M3 在 M2 之上开衔接层；M4/M5 属交付工程，前三个核心不跑通无意义；M9 在 M8 之后加「对 agent 的 /v1 服务软停（不动底座）」；M10 在 M6 指针底座上扩展改目录能力并回归壳层登录入口。

> 2026-09-04 排期拆分（详见 [M6 文档](M6-数据持久化与日志/M6-数据持久化与日志.md) 头块）：M6 定为**数据底座**；GUI 日志历史浏览拆为 **M7**、Token 统计页顺延为 **M8**、设置页（改数据目录）立为 **M10**；同期插入 **M9 服务开关**。
>
> 说明：自 **「分端口-停止真关agent端口」** 起，新需求不再使用序号，直接按需求名收录进「需求列表」，插入顺序不影响已有条目编号。

## 文档约定

- **命名**：子目录 + `<需求名>.md`；**新需求用需求名，不编序号**。历史需求沿用 `M<序号>-<名>` 目录名保留。
- **头块**：状态、优先级、来源（开发计划章节 / M1 结论 / 评估结论）、定稿日期（如已定稿）。
- **正文结构**：背景/目标 → 设计方案（含被否决的备选与否决理由）→ 已知边界 → 验收（状态翻转为「已实现」前必填）。
- **状态流转**：规划中 → 方案已定稿 → 开发中 → 已实现。
- 需求状态变化时同步更新本总览表。

# 日志页重构（请求视角 + 事件时间线 + 原始错误）

> **状态**：方案已定稿（2026-10-17；用户拍板：事件流 + 请求汇总表 / 原始 message+body 截断脱敏）
> **优先级**：交付
> **来源**：2026-10-17 日志与统计需求重评估。用户反馈：详情列塞太多、字段需要拆开、要能看到服务端原始错误、要补更多日志字段；参考 cc-switch / sub2api 的日志/统计交互（仅统计部分）。
> **依赖**：《[可观测性数据底座](../可观测性数据底座/可观测性数据底座.md)》（`request_id`、`requests` 表、原始错误、TTFB/tps）；《[窗口尺寸与响应式布局](../窗口尺寸与响应式布局/窗口尺寸与响应式布局.md)》（wide/medium/narrow 三档断点）
> **定稿日期**：2026-10-17

## 1. 背景与目标

现有 [Logs.vue](../../../frontend/src/views/Logs.vue) 是 4 列事件表（时间/类型/模型/详情），所有信息挤在 `detailOf(row)` 里：

- `chat_request` 的 tools/thinking/protocol、`chat_done` 的 tokens/duration、`chat_error` 的 error、`wb_pick` 的账号信息，全在「详情」一列；
- 一次请求被拆成 `chat_request` / `wb_pick` / `auth_401_refresh` / `chat_done|chat_error` 多行，无法一眼看出链路；
- 错误只显示转换后的消息，看不到上游原始 message/body/status/code；
- 无法按供应商、协议、账号、错误类型、request_id 筛选；无法排序、导出、自定义列；
- 手写表格/按钮与其它页面的 Naive UI 风格不统一。

### 目标

| # | 功能 | 说明 |
|---|---|---|
| F1 | 请求视角 | 默认一请求一行（`/v1/requests`），支持展开/抽屉查看完整事件时间线 |
| F2 | 事件视角 | 保留事件流水（`/v1/logs`），作为排障视图，可切换 |
| F3 | 列拆分 | 时间/状态/请求 ID/模型/供应商/协议/耗时/TTFB/tok/s/Token/账号/错误等独立列 |
| F4 | 原始错误 | 详情抽屉展示转换后消息 + 上游原始 message/body/status/code/displayTips，可复制 |
| F5 | 筛选与搜索 | 时间预设、状态、供应商、模型、协议、端点、流式、账号、错误类型、request_id、关键词 |
| F6 | 交互 | 列显隐/排序、分页、暂停自动刷新、复制、导出 CSV、按条件清空 |
| F7 | UI 统一 | 全部使用 Naive UI 组件；抽共享 `PageHeader`/`FilterBar`/`DetailDrawer`/`EmptyState` |

### 非目标

- ❌ 不做统计图表/多维聚合（归《[统计页重构](../统计页重构/统计页重构.md)》）。
- ❌ 不保存/展示成功请求正文与完整 messages（数据底座边界）。
- ❌ 不做日志云端同步、告警、定时导出。
- ❌ 不改 relay 协议语义；只消费新 API。

## 2. 设计方案

### 2.1 数据源与视图切换

| 视图 | 数据源 | 用途 |
|---|---|---|
| **请求视角（默认）** | `GET /v1/requests` + `GET /v1/requests/{request_id}` | 日常排查：一次请求一行；点开看时间线 |
| **事件视角** | `GET /v1/logs` + 新筛选参数 | 深度排障：按事件类型/时间顺序看原始流水 |

顶部用 `NRadioGroup`/`NSegmented` 切换；切换时保留时间/模型/供应商等通用筛选，清空仅属于该视图的筛选。

### 2.2 页面布局

```
┌ PageHeader：请求日志   [自动刷新 2.5s] [暂停] [刷新] [导出] [清空] ┐
├ FilterBar：时间预设 | 状态 | 供应商 | 模型 | 协议 | 流式 | 账号 | 错误类型 | 更多筛选 ┤
│            请求ID搜索 | 错误关键词搜索 | [重置]                          │
├ ViewToggle：请求视角 / 事件视角                                          │
├ DataTable（服务端分页，默认 50/页）                                      │
│  时间 | 状态 | 请求ID | 模型 | 供应商 | 协议 | 耗时 | TTFB | tok/s | Token | 错误 │
├ Footer：本页 N 条 · 共 M 条 | 分页                                       │
└ DetailDrawer（点击行打开）                                               ┘
```

### 2.3 请求视角表格

默认列（可在列设置中增减）：

| 列 | 内容 | 说明 |
|---|---|---|
| 时间 | `started_at` 本地时间 | 今天只显示时刻；悬浮显示完整时间 |
| 状态 | `success` / `error` / `in_progress` / `interrupted` | 彩色 `NTag`；error 显示 HTTP/上游 code |
| 请求 ID | `req_xxx` 短形式 | 点击复制；悬浮完整 |
| 模型 | `model_requested` | 悬浮显示 `model_bare` / `model_upstream` |
| 供应商 | `provider` | 牛码 / WorkBuddy CN / WorkBuddy 国际 / 自定义名 |
| 协议 | `protocol` + `endpoint` | `chat` / `responses` / `anthropic` |
| 耗时 | `duration_ms` | `ms` / `s` 自适应 |
| TTFB | `first_token_ms` | 非流式显示 `—` |
| tok/s | `tokens_per_second` | 1 位小数 |
| Token | `total_tokens` | 悬浮显示 prompt/completion/cached/reasoning |
| 账号 | `account_uid` 短形式 + 昵称 | 仅账号型平台 |
| 错误 | `error_kind` + `error_message` 截断 | 悬浮完整；点开抽屉看原始体 |
| 重试/换号 | `retry_count` / `switch_count` | 可选列 |
| 客户端 | `client_agent` | 可选列 |

列设置：

- 列显隐/顺序存 `localStorage`（键 `logsColumns`）；
- 默认精简列，避免横向溢出；
- 支持按时间/耗时/TTFB/tok/s/Token 排序（服务端排序参数由数据底座 API 提供；若首版仅支持时间倒序，则其余列先做前端排序，需在实现时明确）。

### 2.4 事件视角表格

列：时间、类型、请求 ID、模型、供应商、协议、账号、摘要（按 kind 渲染）、详情。

- `chat_request`：工具数、流式、思考档位、协议；
- `chat_done`：tokens、耗时、TTFB、tok/s、finish_reason；
- `chat_error`：error_kind、HTTP/code、error_message；
- `wb_pick`：账号、优先级、attempt_index、pick_reason；
- `auth_401_refresh`：attempt/status。
- 点击行 → 同一个 DetailDrawer（显示该事件 + 所属请求时间线）。

### 2.5 筛选与搜索

| 筛选 | 控件 | 说明 |
|---|---|---|
| 时间 | `NDatePicker` + 预设按钮 | 15m / 1h / 6h / 24h / 7d / 30d / 全部 / 自定义 |
| 状态 | `NSelect` 多选 | success/error/in_progress/interrupted |
| 供应商 | `NSelect` 多选 | facets |
| 模型 | `NSelect` 多选 + 搜索 | facets；供应商变化时可选级联 |
| 协议 | `NSelect` 多选 | chat/responses/anthropic |
| 端点 | `NSelect` 多选 | 放在「更多筛选」 |
| 流式 | `NRadioGroup` | 全部/流式/非流式 |
| 账号 | `NSelect` 多选 + 搜索 | 账号型平台 |
| 错误类型 | `NSelect` 多选 | error_kind facets |
| 客户端 | `NSelect` 多选 | client_agent facets |
| request_id | `NInput` | 精确/前缀匹配 |
| 关键词 | `NInput` | 在 `error_message` / UA / request_id 中模糊匹配 |

「更多筛选」用 `NPopover` 收纳低频项；筛选变化后页码重置为 1。

### 2.6 详情抽屉

`NDrawer`（右侧，宽度 720–880px），头部：状态徽标 + 请求 ID + 复制按钮 + 关闭。

页签（`NTabs`）：

1. **概要**
   - 时间（开始/结束）、模型（requested/bare/upstream）、供应商、协议/端点、流式、客户端、账号、状态、重试/换号次数。
2. **Token 与性能**
   - prompt/completion/cached/reasoning/total；
   - duration、TTFB、tok/s、finish_reason、content_chars/reasoning_chars/tool_calls_count；
   - 缓存命中率（cached/(prompt+cached)，tooltip 注明上游口径）。
3. **请求参数**
   - temperature、max_tokens、tool_choice、response_format、thinking/thinking_effort、tool_mode；
   - message_count、角色分布、has_tools、has_images、tool_count、probe。
4. **上游错误**
   - `error_message`（转换后，主展示）；
   - `http_status` / `upstream_code` / `error_kind` / `error_stage` / `retryable`；
   - `upstream_raw_msg`；
   - `upstream_raw_body`：等宽代码块，最大高度滚动；顶部显示「原始 N 字节 / 已截断 / 已脱敏」；
   - `displayTips`；
   - 复制原始响应按钮；
   - 非错误请求显示「无错误」空态。
5. **事件时间线**
   - 按 `logs.id` 升序：`chat_request` → `wb_pick`（可多条）→ `auth_401_refresh`（可多条）→ `chat_done|chat_error`；
   - 每条事件显示时间、类型、关键摘要；错误事件红色；选号事件显示账号/优先级/attempt；
   - 支持点击事件展开原始 JSON（`detail`）。

### 2.7 操作

- **自动刷新**：请求视角默认 2.5s 轮询第一页；暂停后停止；事件视角同样支持。
- **刷新**：手动重新拉取当前页 + facets。
- **导出**：按当前筛选导出 CSV（请求视角）或 JSON（事件视角）；前端分页拉取，上限 10,000 行，超出提示缩小范围。CSV 列与当前可见列一致；默认不含原始错误体（可选勾选「包含原始错误」）。
- **清空**：
  - 请求视角：`DELETE /v1/requests` + 当前筛选；二次确认；提示会同时删除关联事件；
  - 事件视角：`DELETE /v1/logs` + 当前筛选；
  - 无筛选 = 全清；显示删除条数。
- **复制**：request_id、原始错误、单行摘要。
- **列设置**：`NPopover` + 复选框；恢复默认。

### 2.8 UI 与组件

全部使用 Naive UI（规则 7）：

- `NDataTable`（服务端分页、排序、列配置）、`NDrawer`、`NDescriptions`、`NTabs`、`NSelect`、`NDatePicker`、`NInput`、`NRadioGroup`/`NSegmented`、`NTag`、`NButton`、`NPopover`、`NTooltip`、`NEmpty`、`NSpin`、`NPagination`（或表格内置）。
- 抽共享组件到 `frontend/src/components/observability/`：
  - `PageHeader.vue`（标题 + 右侧操作）
  - `FilterBar.vue`（筛选布局 + 更多筛选）
  - `StatusTag.vue`（success/error/in_progress/interrupted）
  - `StatCard.vue`（统计页复用）
  - `DetailDrawer.vue`（日志/统计钻取复用）
  - `EmptyState.vue`
- 颜色/间距/字号沿用现有 `cp-*` 变量；不再手写 `.tbl`/`.dim-btn` 一类样式。
- 响应式：按《[窗口尺寸与响应式布局](../窗口尺寸与响应式布局/窗口尺寸与响应式布局.md)》三档断点——<1280 隐藏低优先级列并让筛选换行；<1100 侧栏收图标 rail、筛选低频项收进「更多筛选」、详情抽屉全宽；表格横向滚动，**不允许页面级横向滚动**。

## 3. 已知边界

- **旧日志无 request_id**：请求视角只显示升级后的请求；事件视角仍可查旧行（`request_id` 显示 `—`）。
- **原始错误只对错误请求有**：成功请求显示「无错误」；原始体 8KB 截断 + 脱敏。
- **不展示成功正文**：只展示元信息；请求参数来自入站解析，不含 messages 正文。
- **导出上限**：前端分页拉取 10,000 行；更大范围后续加后端流式导出。
- **排序**：首版至少时间倒序；其它列若后端未提供排序参数，先做当前页前端排序并在表头标注。
- **实时性**：轮询 2.5s，非 SSE。
- **清理级联**：请求视角清空 = 删除 `requests` + 关联 `logs`；事件视角清空 = 只删除 `logs` 事件，保留 `requests` 汇总行（汇总行仍可在请求视角查看，只是时间线为空）。UI 文案需明确两者差异。

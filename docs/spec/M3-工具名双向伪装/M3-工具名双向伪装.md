- **状态**：已实现（2026-09-03）

- **优先级**：核心

- **来源**：开发计划 §3.3/§3.4（M1 结论：牛码容忍未知工具名）；参考实现 的 `ta3_tool_aliases.py` / `ta3_tool_schemas.py`

- **定稿日期**：2026-09-03

- **实现说明**：新增 `relay/relay/tool_disguise.py`（三模式编排 + agent 扩展映射 + 请求级映射表）；vendored `ta3.py` 最小化改造（新增可选参数 `tool_mode/disguise_map/restore_map/args_*`/`tools_pre_disguised`，默认行为与 M2 完全一致），接收请求级映射表完成历史消息伪装与入站还原。启动：`python run.py run [--tool-mode hybrid|strict|passthrough]` 或环境变量 `TOOL_MODE`。

## 需求背景

牛码模型是官方桌面端的原生工具集（PascalCase：`Read/Edit/Bash/SubAgent`）。第三方 agent 的工具名五花八门（`fs_read/editor_apply_diff/glob/apply_patch`）。参考实现 的做法是「边界翻译+身份伪装」：出站把自家工具整体替换成牛码原生 schema，回包再反伪装；无映射的长尾**直接舍弃**（模型根本不知道）。

relay 面对任意 agent，长尾舍弃=能力残缺，但已由 M1 探针确认**牛码网关容忍任意工具名**，因此 hybrid 长尾可**透传保留**而不会炸会话。

## 设计目标

三种模式，默认 hybrid；工具名/schema 在出站、入站双边做映射，回包还原给 agent 真实工具名。

## 设计方案

### 1. 双向映射表（vendored 自 参考实现）

`TO_TA3`（真实→牛码）、`FROM_TA3`（反查）、`ARGS_TO_TA3`/`ARGS_FROM_TA3`（参数键名互转，`None`=丢弃）、`SPAWN_FORCED_ARGS`（牛码无后台子代理，强制同步 explore）。schema 用 `TA3_NATIVE_SCHEMAS` 整体顶替（非只改 name）。

### 2. 三种模式

| 模式            | 有映射工具      | 无映射（长尾）工具         |
| ------------- | ---------- | ----------------- |
| `hybrid`（默认）  | 重命名 + 参数适配 | **透传保留**（M1 确认容忍） |
| `strict`      | 同上         | 丢弃（对齐 参考实现）  |
| `passthrough` | 原样透传，不做映射  | 原样透传              |

- 系用时的长尾**透传**：只把 tools schema 原样交给牛码；若模型中返回了 agent 真实的未知名 `tool_calls`，relay 转回前端时**保持原名**，由 agent 侧执行——relay 只管转发不执行。

- 历史消息里的未映射调用：转发时降级为文本占位（对齐 参考实现），避免协议断裂。

- 入站未知名：保持原样透传（执行错误归 agent）。

### 3. 回包反伪装

牛码返回的 `tool_calls.name`（牛码名）→ `FROM_TA3` 还原为真实名 + `ARGS_FROM_TA3` 还原参数键，agent 才执行得了。

## 否决的备选

- **纯 passthrough（不做映射）**：PascalCase 工具名语义差、与 agent 不匹配，且失去核心"伪装"价值，定位为最简回退而非默认。

- **strict（复刻 参考实现 丢弃）**：长尾能力全丢，违背 relay「接入任意 agent」的定位；仅作严格模式。

## 已知边界

- 映射覆盖不了 agent 的自定义长尾（走透传，不保证牛码语义理解精确）。

- `SubAgent` 无后台模式差异（同步探索），经 `SPAWN_FORCED_ARGS` 兜底；语义仍与 agent 后台子代理有出入。

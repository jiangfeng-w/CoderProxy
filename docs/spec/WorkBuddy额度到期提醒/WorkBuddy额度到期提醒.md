# WorkBuddy额度到期提醒

> **状态**：方案已定稿（2026-10-16；对齐参考实现 1.13.0 评审的 P2 项，用户「按建议来」纳入排期）
> **优先级**：交付（前端为主，后端零改动）
> **来源**：workbuddy2api-panel 1.13.0 对齐评审——到期卡片（`acb3830`/`6bc832c`/`bb8fd1d`）、**按需拉取**教训（`8391a05`：打开页面即逐号打上游会把面板卡死）、快照渲染修死锁（`0ab6690` issue #145）、逐包按到期排序（`1b90f7f` issue #125）
> **前置**：WorkBuddy多账号登录与签到（`quota.packages` 逐包落库已具备）+ 双域账号支持（CN/国际版同款数据形态）

## 背景 / 目标

现有额度展示已含逐包明细（`quota.packages[] = {name,total,used,remaining,expire_at,cycle}`，后端已读
`DeductionEndTime`——周期包取 `CycleEndTime` 轮换点、一次性包取真实到期；`quota.expire_at` 为最早未来到期），
但前端**不做到期视角的呈现**：逐包表格按上游返回序渲染、账号卡没有「快到期」提示——「积分要用不完了」
是 WorkBuddy 用户最实际的损耗点（代理按 FEFO 扣包，过了抵扣窗口即作废）。

本期（前端为主）：

1. **逐包明细默认按到期升序**（无到期/长期有效垫底），并提供「按到期 / 按面额」排序切换（choices 持久化 localStorage）；
2. **账号卡「最近到期」提醒行**：显示该号最早到期批次与剩余（阈值分级：≤7 天醒目）；
3. （可选）账号区顶部汇总：「N 个账号 7 天内到期，合计 X」。

### 硬约束（参考实现踩坑教训，必须遵守）

- **不新增上游请求**：提醒数据一律取**已落库的 `quota`**（快照渲染）——「刷新配额」时才更新快照；
  **禁止**在页面加载/切 tab 时逐账号实时拉包（参考实现 8391a05 的教训：packages 是逐账号实时查上游，账号一多打开面板就卡死）。
- 快照数据可能过期：提醒行标注「配额数据截至 <fetched_at>」，避免用户误判。

## 设计方案

### 核心决策

| 决策 | 结论 |
|---|---|
| 排序默认值 | 按 `expire_at` 升序；空 `expire_at`（长期有效）垫底；同到期时刻按剩余额度降序 |
| 排序持久化 | localStorage（键 `wbQuotaSort`），取值 `expiry`（默认）/`amount` |
| 提醒阈值 | ≤7 天「即将到期」（醒目色）；≤30 天「关注」（次要色）；>30 天/长期不显示 |
| 数据源 | 账号卡 `quota.packages` 与 `quota.expire_at`（既有字段，无后端改动） |
| 双域 | 同款组件两 tab 通用（CN 优先验收；国际版数据形态同构） |

### 修改文件

```
frontend/src/views/providers/WorkBuddyTab.vue   # 明细排序 + 排序切换器 + 账号卡到期提醒行
frontend/src/stores/workbuddy.ts（如需要）       # 排序选择状态（localStorage 持久化）
docs/spec/WorkBuddy反代账号池健康管理/            # 无（倒计时是另一需求，勿混）
```

后端**零改动**（数据已齐）；不新增端点、不新增配置键。

## 已知边界

- 免费号/企业号额度形态差异：企业号额度走个人端点为空（另见对齐评审的企业版待办）——本期不做企业分流，无数据时提醒行不显示；
- 周期包 `expire_at` 是**下轮权益刷新点**（非作废时刻），提醒文案用「将于 X 刷新（周期包）」区分一次性包「将于 X 到期」。

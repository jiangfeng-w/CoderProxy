## 1. 需求（用户原话语义，2026-10-11）

模型列表的思考强度档位优化：

1. 新增一个软件内档位「**透传**」：语义 = 直接透传 agent 传过来的思考强度，**软件不对思考强度做任何干扰**；且**默认选择该档位**；
2. 选择了其他档位 = **强制**：把思考强度改到该档位，**即使 agent 传了思考强度参数也没用**；
3. 之前预留的「真关/假关」变量与计划随之**移除**（评估结论：预留从未接线，属死代码，见 §4）。

## 2. 设计方案（拍板：形状归一透传）

### 2.1 两档语义

| 档位 | 语义 | 出站形状 |
|---|---|---|
| **透传**（默认，未配置 = 透传） | agent 表态则按官方客户端形状翻译；agent 未表态则零注入零兜底（上游默认行为） | 见 2.2 |
| **具体档**（关/low/high/max/…） | 强制：无视 agent 传参，按官方客户端形状下发该档 | 关：deepseek 系 `thinking:{type:"disabled"}`（BUG-3 探针背书）/ 非 deepseek `reasoning_effort:"none"` 直发（B4 实证）；档：`thinking:{type:"enabled"}` + 档位 + `reasoning_summary:"auto"`（deepseek 系）/ 档位 + summary（非 deepseek） |

**「透传」的定义 = 形状归一，不是严格零触**（用户拍板 2026-10-11，采纳推荐口径）：

- agent **表态了** → 按官方客户端形状翻译出站（形状翻译不是档位干扰）：
  - deepseek 系：开意图 → `thinking:{type:"enabled"}` + agent 原档（**不降级不改写**）+ summary:auto；
    **关意图（effort ∈ none/off/disabled 或 thinking=False）→ `thinking:{type:"disabled"}`**
    ——唯一特例，缘由：deepseek 系裸 `reasoning_effort:"none"` 上游不认（BUG-3 探针实证仍出思考），
    不翻译则 agent 的关意图失效；非 deepseek 模型裸 none 有效（B4 实证），无需特例；
  - 非 deepseek：维持 B4 形状（effort 直发、off 删字段、非 none 配 summary:auto）；
- agent **未表态** → 什么都不发（不再有「未配置 = none 强制关」的隐藏兜底——行为翻转见 §5）。

### 2.2 关键决策与理由

- **enforcement 位置 = routes 层统一覆写**（方案 A）：强制档在 adapter dispatch 前覆写
  `chat_request.thinking=True + reasoning_effort=<档>`（关 = effort="none"，两家 adapter 的既有
  关路径自然接住：ta3 → thinking:disabled / WB deepseek → 真关、非 deepseek → none 直发）；
  透传 = 不碰 chat_request。三链路（牛码/WorkBuddy/自定义）一处生效，牛码 ta3 侧**零改动**。
- **`_downgrade_effort` 一并删除**：强制档的值来自 GUI 目录内选项；目录外档位 UI 已标注
  「不保证生效」，尊重用户选择原样发，不再降级改写。
- **每模型默认档兜底（`_entry_default_effort` / `oai_adapter.apply_thinking_default`）退役**：
  兜底语义被「透传（默认）+ 显式强制档」二元取代，不存在「agent 没传时替 agent 选档」的行为了。

### 2.3 被否决的备选

- **严格零触透传**（agent 说 none 就原样发 none）：否决——deepseek 系裸 none 关不掉
  （BUG-3 探针实证），agent 的关意图会被上游怪癖吞掉；且仅在 deepseek 系需要特例，
  形状归一的代价极小而语义保真完整。
- **设置页全局「真关/假关」开关（原 F3 计划）**：作废——其回答的问题（agent 没传时全局兜底
  怎么选）被「透传 = 不兜底」消解；且该开关从未接线（见 §4）。

## 4. 数据与兼容

- `thinking_defaults` 值域扩为 `{none | 目录档位 | "passthrough"}`；未配置 = 透传；
- **语义迁移**：已配置的档位值从「agent 没传时的兜底」变为「强制」（用户拍板的语义本身）；
- **行为翻转**：未配置模型从「隐藏兜底 none = 强制关」→「透传」。不表态的裸脚本客户端将落
  上游默认思考（可能烧 token）——主流 agent（ZCode 等）均表态思考参数，风险面小；真在意可
  在模型页给个别模型设强制关。**写进验收**；
- `thinking_unset_mode` 落盘键残留无害（读侧删除后无人读取）；
- 透传保真度受限于入站协议归一层（ChatRequest 只有 thinking/reasoning_effort 两个字段，
  未识别的原始思考形态在归一时已处理——BUG-005 三协议统一提取）。

## 5. 验收标准

1. 档位=透传（默认）：agent 传档 → 上游收到的 reasoning_effort 与 agent 原值一致（不降级）；
   agent 传关 → deepseek 系出 `thinking:{type:"disabled"}`、非 deepseek 出 none 直发；
   agent 未表态 → 出站 body 无任何思考字段；
2. 档位=具体档 X：无论 agent 传什么（含冲突档位/关意图），出站一律 X 的强制形状；
3. 三协议入站（chat/responses/messages）语义一致（归一层已有 BUG-005 统一提取保障）；
4. GUI：模型区档位下拉含「透传」且为默认显示值；列语义文案更新；
5. 全量 pytest 绿（含改写后的思考形状测试 + 新增强制覆写测试）；ruff 零新增；
6. 小号探针（≤3 请求）：`thinking:{type:"enabled"}` 无档位（agent 只表态开、未给档）上游行为
   观察一次，结果回填本节；
7. sidecar 重建 + dev 实测：ZCode 真实请求日志 `thinking_effort` 与 agent 端设置一致。

### §5-6 探针回填（2026-10-11，`探针-wb-thinking-enabled-无档位.py`，小号固定 2 请求）

deepseek-v4.1-flash，直连上游：

- **P0 基线**（enabled + effort=high）：200，**reasoning 流出现**（delta.reasoning_content
  非空）——账号/形状 sanity 通过，判定法有效；
- **P1 观察**（enabled + summary:auto，**无档位**，即透传归一出站形状）：200，**无 reasoning
  流**（usage 的 reasoning_tokens 字段该形状下不回报，以流信号为准）。

**结论：缺档 = 上游不出思考**——`thinking:{type:"enabled"}` 缺 `reasoning_effort` 时
isThinkingEnabled 判定不亮（summary:auto 单独不亮），agent「只表态开、未给档」在透传下
**等效不思考**（200 放行、零思考开销）。与 thinking.go 逆向口径一致；形状归一现状成立，
无需兜底补档。附注：该形状 usage 不带 reasoning_tokens 字段，日志页对零表态请求本就
不展示思考段，无呈现影响。

### §5-8 glm-5.3-flash「关思考」探针（2026-10-11，`探针-wb-glm53flash-关思考.py`，小号固定 4 请求）

起因：用户实测 glm-5.3-flash 选「关」→ 日志显示思考关、客户端仍见思考输出。矩阵结果
（判定信号 = reasoning 流；该上游 usage 常不回报 reasoning_tokens）：

| 形状 | 结果 |
|---|---|
| P0 基线（无思考字段） | 200，**默认思考**（判定法有效） |
| P1 `reasoning_effort:"none"`（现行关形状） | 200，**仍思考——关无效** |
| P2 `thinking:{type:"disabled"}` | 200，**仍思考**（WB 网关不报 400、静默忽略） |
| P3 `reasoning_effort:"minimal"`（缓解候选） | 200，**仍思考**（不在其档位表） |

**结论：WB 上游对 glm-5.3-flash 不支持关闭思考**——none/disabled/minimal 全被忽略落回
默认思考。与 2026-09-06 调研吻合（GLM-5.3 系仅认 low/high/max；智谱直连报错而 WB 网关
静默忽略）；B4「none 真关」仅在 deepseek 系成立，**非 deepseek 一律 none 直发的关路径
对 glm-5.3 系无效**。牛码侧同模型无法实测（主号封禁），按调研推断同样关不掉。

**缓解选项（待用户拍板）**：① relay 对 `glm-5.3` 前缀把关意图翻译成
`thinking:{type:"enabled"}` + 目录最低档 low（对齐智谱官方网关「关→low」语义，
形状无歧义、思考最省，代价是「关」语义失真为「最低档」）；② 维持 none 直发 +
GUI/文档标注「该模型上游不支持关思考」（诚实但实际效果=默认档思考，日志「思考关」
与事实不符）；③ GUI 对该系禁选「关」。选定前代码维持现状。

**拍板（2026-10-11）**：上网核实后选**方案 2「维持现状 + 前端标注」**。核实结论
（一手来源，与探针互证）：z.ai 官方文档明确 GLM-5.3/5.3-FLASH "use forced thinking
and cannot be disabled"（`thinking.type:"disabled"` 仅适用 GLM-4.6 及更早系列）；
官方博客 "Disabling thinking is no longer supported by GLM-5.3"；官方模型卡
`reasoning_effort` 仅 low/high/max；直连智谱报 400/1210「该模型始终思考，不支持关闭
思考；请使用 low、high 或 max」。落地：relay 下发不改（none 照发）；`store.ts` 新增
`offThinkingUnsupported()`（包含匹配，兼容 `牛码/` 前缀 id——旧 `startsWith` 在带前缀
id 上永不命中，属死代码）；模型下拉「关」选项对 glm-5.3 系加「· 上游不支持」后缀 +
tooltip 更新为实测结论；日志页「思考关」追加「（上游不支持，仍思考）」。方案 1
（关→enabled+low 映射）备选记录在案：若后续用户反感「选关仍思考」可再启用。

**「关」标注三态化（2026-10-11，用户反馈后）**：上游目录 `thinkingLevels` 均不含
none（deepseek 也只有 low/high/max 等），「关」无法用目录数据自动标注，故在
`store.ts` 维护实测清单 `offThinkingSupported()`（deepseek 系——B4 实测真关；
kimi-k3——2026-09-06 实测正常关且未降级）。下拉「关」标注：glm-5.3 系「·上游不支持」
（比目录外更强的确定结论，保留方案 2 警示）＞ 已实测支持「·上游」＞ 其余「·目录外」
（无实测数据，不保证生效）；tooltip 同步三态。日志页标注不变（仅 glm-5.3 系追加）。

**「关」支持面联网核实（2026-10-11，用户要求先查证再标注）**：对全部 16 个有档位
模型逐族核实官方文档，`offThinkingSupported` 扩为 `deepseek-v3/v4 系 + kimi-k3 +
glm-5.2`：

| 模型族 | 官方能否关思考 | 依据 / 证据 | 标注 |
|---|---|---|---|
| glm-5.3 / 5.3-flash | ❌ 强制思考 | z.ai docs "forced thinking and cannot be disabled"；直连 400/1210；WB 探针静默忽略 | ·上游不支持 |
| glm-5.2 | ✅ | 智谱官方文档：`thinking.type` 支持 `disabled`，传 `none/minimal` 放弃思考（GLM-4.7/4.5V 亦强制，但无档位下拉） | ·上游 |
| deepseek-v3/v4 系 | ✅ | DeepSeek 官方 `thinking:{type:"enabled/disabled"}` 开关（anthropic 格式 `reasoning.effort:"none"`）；B4 探针 WB 实测真关 | ·上游 |
| kimi-k3 | ⚠️ 官方 API 始终思考 | Moonshot 官方文档：K3 无 `thinking` 参数、仅 `reasoning_effort` low/high/max；官方客户端「关」= 路由到 K2.8 无思考版本；WB 小号实测关后无推理输出、未降级（观测一致） | ·上游 |
| hy3 / hy4-preview（混元 Hy3/Hy4） | Hy3 官方有 `enable_thinking` 快慢思考开关 | 但 WB 网关对该系的关形状（`reasoning_effort:"none"`）未实测，无法确认转发 | ·目录外 |
| kimi-k2.8-preview / space-bunny | 无官方证据 | Kimi 官方 thinking 文档仅列 k3/k2.7-code/k2.6（k2.6 可 `disabled`），K2.8 未列 | ·目录外 |

要点：relay 现行关形状（非 deepseek = `reasoning_effort:"none"`、deepseek =
`thinking:{type:"disabled"}`）恰好与 glm-5.2 / deepseek 的官方认可形状吻合，标注
「·上游」有据；hy3/hy4 官方虽支持关，但走的是 `enable_thinking` 形状、WB 是否代翻
未知，保守标「·目录外」，待小号探针验证后再升级。

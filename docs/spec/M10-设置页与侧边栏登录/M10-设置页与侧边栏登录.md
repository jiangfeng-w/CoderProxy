# M10 设置页与侧边栏登录（数据目录修改 + 登录入口移到侧边栏）

> 状态：部分已实现（侧边栏登录 已实现 2026-09-04；思考兜底策略开关 已实现 2026-09-06，暂挂 Config.vue 见 §7；数据目录 规划中）
> 优先级：交付
> 来源：① 数据目录共享指针新需求（2026-09-04 用户拍板）：AppData 只存指针文件，便携版 / 安装版共享同一数据目录；用户可修改数据存放位置。② 用户明确「登录状态/按钮从顶栏移到侧边栏底部」，做成头像+用户名整行可点、弹菜单含「退出登录」，并配合 M9 的服务开关在登录后才显示「运行中」
> 依赖：M6 数据底座（数据默认落 AppData + 指针文件 `data_path.txt`，即 M6 §2.6；本里程碑在底座上实现「查看 / 修改」能力）；UI 基建可复用 M7 之后的 Config.vue / api.ts / M9 服务开关（`/v1/service`）
> 定稿日期：—（侧边栏登录已定稿详见 §6）

## 1. 背景与目标

M6 已实现共享指针底座：`app_data_dir/data_path.txt` 记录真实数据目录，默认指向 `app_data_dir/data`。本里程碑补上**用户侧入口**：GUI 展示当前真实数据目录，并允许修改到新位置（迁移全部数据 + 原子更新指针 + 重启服务）。改完后便携版 / 安装版仍经同一指针共享新目录。

### 目标

| # | 功能 | 说明 |
|---|---|---|
| F1 | 展示当前数据目录 | 只读展示指针解析出的真实目录绝对路径（可附带目录占用大小，延后） |
| F2 | 更改数据目录 | 选新目录 → 校验 → 整体迁移 → 原子更新指针 → 重启 sidecar → 结果反馈 |
| F3 | 迁移失败可回滚 | 任一步失败不破坏旧目录与旧指针，提示原因可重试 |
| F4 | 变更前风险提示 | 告知迁移对象（登录态 / 白名单 / 端口 / 日志库）与期间服务短暂重启 |
| F5 | 目录选择 | 原生目录选择器；目标可写 / 可建 / 非空等校验 |

### 非目标

- 不做数据目录的加密 / 多用户。
- 不做目录占用可视化（仅文本路径 + 可延后的大小）。
- 不改变 M6 的指针读取规则（首次解析、共享语义归 M6）。

## 2. 设计方案

### 2.1 前置：M6 指针底座（不在本期重复）

M6 已落地：`resolve_data_dir` 指针优先、默认 `app_data_dir/data`、首次启动写指针、旧 `relay_state.json` 一次性迁移。本里程碑只依赖它，**不改解析规则**，只实现「改指针 + 迁数据 + 重启」这一写路径。

### 2.2 Rust：新增 `change_data_dir(new_path)`（tauri command）

执行顺序（**先停服 → 复制校验 → 更新指针 → 清理旧源 → 启服**，不能先删源后改指针）：

1. **校验**：new_path 可写可建；与当前 data_dir 相同 → 拒绝；new_path 已存在且非空（且不含本项目数据）→ 二次确认或拒绝，防覆盖已有目录。
2. **停 sidecar**：避免迁移与运行中 relay 写库竞争（WAL 未 checkpoint 部分复制可能不完整，先停服保证一致快照）。
3. **复制 + 校验**：递归复制当前 data_dir 全部内容（`relay_state.json`、`coderproxy.db` + `-wal/-shm`、未来扩展文件），逐文件校验（大小 / mtime，必要时 hash）；跳过 `.tmp`。
4. **原子更新指针**：写 `data_path.txt.tmp` → `rename` 覆盖（此刻起新启动即命中新目录）。
5. **清理旧源**：删除旧 data_dir 内容（保留目录本身亦可）；失败仅残留可再清，数据已安全在新目录。
6. **重启 sidecar**：以新 `RELAY_DATA_DIR` spawn（复用现有 spawn 链路），返回新就绪状态。

**异常面（迁移中断：断电 / 杀进程）**
- 步骤 3 前中断：指针未动，一切照旧，直接重试；
- 步骤 4 前中断：数据已复制到新目录但指针未更新 → 仍用旧目录，数据完整，重试会再次复制（幂等）；
- 步骤 4 后中断：指针已指向新目录且数据已校验完整 → 旧目录仅残留，可手动清理。
- 不存在「指针已更新但数据未迁完」的中间态（顺序保证）。

### 2.3 指针失效策略（需随 M6 一并确认）

启动时若指针指向的目录不可访问 / 不可写：relay 无法在目标目录建库。策略：**GUI 提示「数据目录不可访问：<path>」，允许在本设置页重选**；期间以隔离的默认目录（`app_data_dir/data` 或临时目录）起服，避免不可用。此策略在 M6 实现指针解析时即需定稿，故在两文档标注（M6 §2.6 / 本 §2.3）。

### 2.4 UI（初拟）

- **位置**：并入现有 [Config.vue](../../../frontend/src/views/Config.vue) 底部新增「数据存储」卡片（避免 Shell 导航膨胀）；若届时导航已需重组，再评估独立「设置」页。
- 交互：当前目录只读展示 + 「更改」按钮 → 原生目录选择 → 二次确认对话框（列出迁移影响与重启提示）→ 进度态（迁移中禁用操作）→ 成功 / 失败反馈（失败显示原因，旧目录数据保留）。
- `api.ts`：`getDataDir()`（读当前目录，可复用 `relay_status`/新增轻量命令）、`changeDataDir(path)`（invoke）。

## 3. 已知边界

- 迁移窗口内服务不可用（数秒级，UI 已提示）。
- 便携版换机器：数据不随 exe 走（指针在 AppData），符合「共享」而非「随身」语义；用户可主动用本设置页迁移到新位置。
- 同一台机器同一时刻仅单实例（M6 §2.6 规则 6 延续）。
- 多版本共存时，任意版本修改目录 = 全局生效（共享同一指针）。

## 4. 验收（实现前必填）

1. 设置页正确展示当前真实数据目录（与指针内容一致）。
2. 改到新目录后：新目录含全部旧数据（登录态 / 模型白名单 / 端口 / 日志库）；指针文件内容 = 新目录；服务重启后仍用新目录。
3. 迁移过程服务先停后启；UI 有进度与结果反馈。
4. 失败路径：目标不可写 / 已存在非空冲突等被拦截并提示，旧目录与旧指针保持完整可重试。
5. 改完后便携版 / 安装版任一启动均命中新目录（共享生效）。
6. 指针失效场景按 §2.3 策略提示与恢复（与 M6 验收同跑）。
7. 前端类型检查（vue-tsc）通过；frontend build / 打包通过。

## 6. 侧边栏登录（登录入口从顶栏移到侧边栏）

> 本节对应已实现改动（2026-09-04）。原「登录状态 / 按钮在顶栏右侧」已移除。

### 6.1 背景与目标

原来登录状态 / 按钮在顶栏右侧（`已登录 <用户名> / 登出 / 登录`）。本期把登录入口移到**侧边栏最底部**：

- 未登录 → 显示「登录」行。
- 登录中 → 明确提示「登录中…」（让用户知道在登录）。
- 已登录 → 头像 + 用户名，**整行可点**，弹出菜单（对齐参考产品图，先加「退出登录」，后续可扩展其它项）。
- 配合 M9 服务开关：未登录时顶栏显示「未登录 · 登录后自动启动服务」，登录后才显示「运行中」。

### 6.2 设计方案

- **布局**：顶栏 `.ops` 移除登录态；侧边栏底部新增 `.user-area`（[Shell.vue](../../../frontend/src/Shell.vue)）：
  - `not_logged_in | failed` → 「登录」按钮（failed 显示「登录失败，点击重试」）。
  - `pending` → spinner + 「登录中…」。
  - `logged_in` → `.user-profile`：头像（用户名首字圆形渐变底，因 `AuthStatus` 无头像 URL）+ 用户名 + 展开符，整行可点。
  - 点击展开 `.user-menu`（弹窗，向上浮出），含用户信息头 + 「退出登录」（红字危险项）。
- **交互**：点组件外自动关闭（document click 监听）；登出复位 `showUserMenu`。
- **服务门控联动**：`serviceRunning = relay.running && store.serviceEnabled`；顶栏状态文案随登录态变化（见 M9 §2.2）。stop 按钮仅服务运行时可用，restart 按钮登录后始终可用。

### 6.3 验收

1. 未登录：侧边栏显「登录」；点击进入 pending（打开浏览器授权），显示「登录中…」。
2. 登录后：侧边栏头像 + 用户名，整行可点弹菜单，「退出登录」可用；顶栏显示「运行中 端口:…」。
3. 点「退出登录」→ 回到未登录，顶栏显示「未登录 · 登录后自动启动服务」。
4. 头像无 URL 时回退为用户名首字。
5. 前端 build / vue-tsc 通过。

### 6.4 支撑

- [Shell.vue](../../../frontend/src/Shell.vue)（侧边栏用户区 + 顶栏门控）、[store.ts](../../../frontend/src/store.ts)（`serviceEnabled`）；relay 侧门控见 M9。

## 7. 思考兜底策略开关（真关/假关）

> relay 侧变量已就绪（2026-09-06）；**GUI 不加临时开关**，待本里程碑设置页落地时一并做进设置页（用户拍板：现阶段行为一切照旧=假关默认）。
> 完整需求背景与实现口径见 [思考强度控制与日志](../思考强度控制与日志/思考强度控制与日志.md)（本节只保留开关本身的落地口径）。

### 7.1 背景与目标

agent 关思考的信号不统一（ZCode 发 `thinking:{type:disabled}`、codex 发 `reasoning_effort:none`、Qwen 系发 `enable_thinking:false`、Trae/opencode 缺省不传）。relay 侧需要定义「agent 不传思考参数时」的兜底语义，由用户拍板：

- **假关（default，默认）**：agent 不传 → 按模型页「默认思考强度」（`thinking_defaults`）下发，缺省=关。保留给不传参的 agent（Trae 等）开思考的能力。
- **真关（off）**：agent 不传 → 一律显式关思考（`thinking:disabled`），忽略每模型默认值。语义最简单、最省 token。

agent 显式传了 `thinking` / `enable_thinking` / `reasoning_effort` 任一 → 一律以 agent 为准，两种模式下都不干预。

### 7.2 实现口径

- relay 配置字段 `thinking_unset_mode`（`default|off`，缺省 `default`），走 `/v1/auth/config` 读写（storage 持久化，损坏值回退 `default`）。
- chat 链路：`oai_adapter.apply_thinking_default(body, req, defaults, unset_mode)`；显式关的入站归一（`thinking:false/disabled` → `effort=none`）与 agent 形态归一（`enable_thinking` 解析）同属本链路。
- GUI：设置页新增「思考兜底策略」开关（样式可复用 Config.vue「工具伪装模式」radio 卡片），读写 `thinking_unset_mode`；前端 `Config` 类型与 config store 已带该字段。

### 7.3 验收

1. 现阶段（开关未上 GUI）：默认假关——agent 不传参时按模型页默认档位下发（未配置=关），行为与开关引入前一致。
2. 设置页切真关后：agent 不传参一律发 `thinking:disabled`，模型页默认值不再生效；agent 显式传参（含显式关）两种模式都尊重。
3. 非法值 400 不落盘；relay 测试与前端 build 通过。

## 1. 背景与目标

### 背景

- 登录入口演进：顶栏登录（M4–M9，main 现状）→ 侧边栏底部用户区（M10 §6，2026-09-04 曾在工作区实现，随清理入 stash `12f5bb21` **未进 main**）。
- WorkBuddy 立项后账号形态质变：单账号「当前用户」→ **多平台多账号池**（牛码单账号 + WorkBuddy 任意数量账号 + 自定义供应商 + Trae/Qoder 扩展位）。「侧边栏头像 = 当前用户」的形态承载不了「每平台若干账号、各有各的状态」。
- 用户拍板（2026-10-07）：不恢复 M10 §6；侧边栏加「供应商」页，登录等账号操作收进去；页内横向标签页分平台，模型管理一并收进牛码标签页（模型页导航项移除）。

### 目标

| # | 功能 | 说明 |
|---|---|---|
| F1 | 供应商页 + 横向标签页 | 侧边栏新增「供应商」导航项；页内 NTabs 横向标签：**牛码 / WorkBuddy / 自定义供应商**（Trae/Qoder 接入后平行加 tab） |

| F3 | 牛码标签页 | 账号区：登录（IM 静默优先/PKCE 兜底）、账号信息、退出（**二次确认**）、同步模型目录（复用 `/v1/auth/*`）；模型区：**原 Models.vue 全部功能迁入**（列表搜索/白名单启停/每模型思考强度/手动连通性测试） |
| F4 | WorkBuddy 标签页 | 账号区：多账号卡片（昵称/配额/签到状态/连签天数）+ 添加/删除/签到/配额刷新——即 WorkBuddy spec 实施步骤 6 的 UI，**直接做成组件挂入本页（跳过独立页过渡）**；模型区：本期占位空态（WorkBuddy 本期不做聊天转发，注明由聚合需求提供） |

### 非目标

- ❌ 自定义供应商的**转发生效**（依赖聚合需求 adapter 层，本期只做配置管理 UI 与存储）。
- ❌ 设置类条目（思考兜底开关、数据目录归设置/M10 数据目录）。
- ❌ 改服务门控逻辑（`_serving() = 已登录 && 未手动停`，relay 侧不变）。
- ❌ 9router 的 combo 编排/代理池等高级形态（归「WorkBuddy聊天反代与多平台聚合」）。

## 2. 设计方案

### 2.1 信息架构（定稿）

```
侧边栏导航: 概览 | 日志 | 统计 | 供应商 | 配置        ← 模型项移除，供应商新增（总数不变）
供应商页（Providers.vue）: NTabs 横向标签页
├─ Tab 牛码
│   ├─ 账号区: 单账号卡片（登录/账号信息/退出二次确认/同步目录；/v1/auth/*）
│   └─ 模型区: 原模型页功能整体迁入（列表/白名单/思考强度/手动测试）
├─ Tab WorkBuddy
│   ├─ 账号区: 多账号卡片网格 + 添加/删除/签到/配额（/v1/platforms/workbuddy/*）
│   └─ 模型区: 占位空态（转发由聚合需求提供）
└─ Tab 自定义供应商
    ├─ 账号区: 供应商条目列表 + 添加/编辑对话框（baseurl/apikey/名称/启停）
    └─ 模型区: 每供应商的模型清单（手填，本期随配置存取）
```

被否决的备选（留档）：
- **侧边栏底部用户区（M10 §6）**：单账号形态产物，装不下多账号池；已废弃。
- **每平台独立导航项**：平台增多后侧边栏膨胀；采纳单一「供应商」页。
- **页内分节平铺（本 spec 初版 2.1）**：升级为横向标签页（2026-10-07 拍板）——平台种类一级维度更清晰，NTabs 现成组件；9router 用卡片网格 + 搜索是其 30+ provider 浏览型场景所需，我们 3-5 类规模不需要。

### 2.2 顶栏与门控分工

- 顶栏**完全移除牛码相关元素**（2026-10-07 三次拍板）：main 顶栏现存的登录按钮、账号名/已登录态、登出按钮随本需求移除；`serviceStatusText` 里的「未登录 · 登录后自动启动服务」「登录中 · …」「登录未完成 · …」等门控文案一并移除，不存在「未登录点击跳供应商页」的顶栏联动。
- 服务状态语义纯化：状态文案只按服务运行/停止输出（如「运行中」「已停止」）；**重启按钮解除牛码登录态绑定**（原 disabled 依赖 `auth.status !== 'logged_in'`，改为仅 busy/服务未运行）。未登录导致服务未运行时顶栏只显示停止态，原因解释由供应商页牛码 tab 账号区承担（未登录卡片态 + 引导登录）。
- 「退出登录」从顶栏挪进牛码 tab 账号区后，因副作用大（清登录态 + 清模型目录 + 服务停止）必须二次确认（NPopconfirm）。
- Shell 的登录态轮询**行为逻辑保留**（登录成功自动同步模型目录、登出检测），仅移除顶栏 UI 与登录态文案；登录/登出动作函数随 UI 迁入牛码 tab 账号区组件。
- 被否决的备选（留档）：**顶栏保留「未登录 · 登录后自动启动服务」门控文案并点击跳转供应商页**（本 spec 初版 2.2）——用户拍板顶栏彻底干净，登录态一律不进顶栏。

### 2.3 前端结构

- `frontend/src/views/Providers.vue`（新）：NTabs 容器 + 三 tab 装配；统一「账号区+模型区」的分区骨架与样式在此定义。
- 牛码 tab：账号区新组件（登录卡片）；模型区抽自 Models.vue（逻辑原样迁移，含空列表轮询、白名单 `__none__` 特殊值语义、手动测试 `probe` 请求）。
- WorkBuddy tab：账号区组件化（`stores/workbuddy.ts` 已在 WorkBuddy spec 规划），作为本页 tab 挂入。
- 自定义供应商 tab：条目列表 + 编辑弹窗（NModal）；数据结构参考 cc-switch `src/types.ts` `Provider{id, name, settingsConfig, icon, sortIndex...}` 精简为 `{id, name, base_url, api_key, enabled, models[]}`（存储与 API 见 §2.4）。
- `Shell.vue`：views 注册表（models 移除、providers 新增）+ 顶栏去登录按钮。

### 2.4 自定义供应商的存储与 API（本期范围）

- 存储：独立 `platform_custom.json`（对齐「WorkBuddy多账号登录与签到」的存储纪律：独立文件 + 独立锁 + tmp.replace 原子写；api_key 为敏感字段，任何 API 响应不得回显——cc-switch 同为单 JSON 明文存储的先例）。
- API：本期仅管理端点（`/v1/providers/custom/*` 增删改查列），转发不接（`build_provider` 不改造，属聚合需求）。
- 配置页（Config.vue）不动：API Key / tool_mode / 端口 / 思考兜底仍归配置页。

### 2.5 与 WorkBuddy 登录签到需求的衔接

- WorkBuddy spec 步骤 6 原述「独立页 + nav 项过渡，落成后迁入」——本页先行后**跳过过渡**：步骤 6 直接产出 WorkBuddy tab 的账号区组件。
- 实施顺序建议：供应商页一期（tabs 骨架 + 牛码 tab 迁移 + 两占位 tab）→ WorkBuddy 后端步骤 1–7 → WorkBuddy tab 填充。

## 3. 已知边界

- 牛码 IM 静默登录依赖本机银海通（`:13631`），账号区需对降级 PKCE 浏览器路径给出提示。
- 模型页功能搬家是本需求最大风险面：Models.vue 的列表/搜索、白名单启停（含全部启用/禁用/`__none__`）、每模型思考强度、手动连通性测试、同步目录、空列表轮询——**逐项列清单验收，一项不能丢**。
- 批量动作沿用现有频控约束（顺序串行；冒烟只用小号——AGENTS 硬性规则 5）。
- 卡片连接状态的「真实请求反哺」依赖同名需求落地；本页首版先显示显式测试结果。
- WorkBuddy/自定义两个 tab 的「模型区」本期为占位/配置态，不做转发联动。

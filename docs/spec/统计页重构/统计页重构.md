## 1. 背景与目标

现有 [Stats.vue](../../../frontend/src/views/Stats.vue) 是 M8 首版：4 张 KPI、1 张图、3 个维度（按天/小时/模型）、3 个筛选（类型/模型/时间），指标只有请求数/成功/失败/各 token。

问题：

- **口径错误**：`/v1/stats` 的 `requests = COUNT(*)` 把 `chat_request`、`chat_done`、`chat_error`、`wb_pick`、`auth_401_refresh` 全算成请求；成功率被稀释。
- **信息少**：没有成功率、缓存命中率、TTFB、tok/s、平均耗时、重试/换号率、错误分布。
- **维度少**：没有供应商/协议/端点/账号/错误类型/流式/思考档位/客户端。
- **交互弱**：没有时间预设、多选筛选、图表指标切换、排序、钻取、导出、自动刷新间隔。
- **UI 不统一**：手写表格/维度按钮，与其它页面的 Naive UI 风格不一致。
- **错误口径无法回答**：慢在哪（TTFB vs 生成）、错在哪（error_kind/上游 code）、哪个账号/供应商不稳定。

### 目标

| # | 功能 | 说明 |
|---|---|---|
| F1 | 正确口径 | 全部统计基于 `requests` 汇总表：一请求一行，不再数事件行 |

### 非目标

- ❌ 不做成本/价格、配额/余额、账单（订阅账号下单请求金额无稳定语义；后续单独立项）。
- ❌ 不做 p50/p95 分位数（第一版只做 avg；作为扩展点保留）。
- ❌ 不做定时报表、邮件/IM 推送、云端同步。

## 2. 数据与 API

### 2.1 数据源

全部统计来自 `requests` 表（数据底座 §2.2），不直接聚合 `logs` 事件行。

口径定义：

- `requests`：`status IN ('success','error','interrupted')` 的请求数；`in_progress` 不计入。
- `success`：`status='success'`；`failed`：`status='error'`；`interrupted`：`status='interrupted'`。
- `success_rate = success / requests`（0 请求时为 0）。
- `error_rate = failed / requests`。
- Token：`SUM(prompt_tokens/completion_tokens/cached_tokens/reasoning_tokens/total_tokens)`。
- `cache_hit_rate = SUM(cached_tokens) / SUM(prompt_tokens + cached_tokens)`（分母为 0 时不产出；UI tooltip 注明上游口径差异）。
- `avg_duration_ms`：仅 `duration_ms IS NOT NULL` 的行取平均。
- `avg_ttfb_ms`：仅 `first_token_ms IS NOT NULL` 的行取平均（非流式不参与）。
- `avg_tps`：仅 `tokens_per_second IS NOT NULL` 的行取平均。
- `avg_tokens_per_request = total_tokens / requests`。
- `retry_rate = COUNT(retry_count > 0) / requests`；`switch_rate = COUNT(switch_count > 0) / requests`。
- `stream_ratio = COUNT(stream=1) / requests`。
- 默认 `is_probe = false`（GUI 连通性探针不污染统计）；用户可显式包含。

### 2.2 新查询 API：`POST /v1/stats/query`

保留旧 `GET /v1/stats` 作兼容（前端切换后不再使用，标记 deprecated）。

请求体：

```json
{
  "time_from": "2026-10-01T00:00:00+00:00",
  "time_to": "2026-10-17T23:59:59+00:00",
  "granularity": "day",
  "dimensions": ["provider"],
  "metrics": ["requests", "success_rate", "total_tokens", "avg_ttfb_ms", "avg_tps"],
  "filters": {
    "provider": ["niucode"],
    "model": [],
    "protocol": [],
    "endpoint": [],
    "account_uid": [],
    "status": [],
    "error_kind": [],
    "stream": null,
    "thinking_effort": [],
    "tool_mode": [],
    "client_agent": [],
    "is_probe": false
  },
  "sort": { "metric": "total_tokens", "order": "desc" },
  "limit": 100,
  "offset": 0
}
```

约束：

- `granularity`: `hour` / `day` / `week` / `month` / `null`；非空时自动增加时间桶维度 `bucket`。
- `dimensions`: 首版最多 **2 个业务维度**（+ 时间桶），避免图表/表格不可读。
- `metrics`: 从下方白名单选择；未传时返回默认集。
- `filters`: 数组字段为多选（OR）；`stream`/`is_probe` 为三态（null=全部）。
- `limit`: 1–500，默认 100；`offset` 默认 0。
- `sort`: 可选；按指标或维度排序。

响应：

```json
{
  "rows": [
    {
      "bucket": "2026-10-17",
      "dimensions": { "provider": "wbcn" },
      "metrics": {
        "requests": 123,
        "success": 120,
        "failed": 2,
        "interrupted": 1,
        "success_rate": 0.9756,
        "prompt_tokens": 1000,
        "completion_tokens": 2000,
        "cached_tokens": 300,
        "reasoning_tokens": 400,
        "total_tokens": 3000,
        "cache_hit_rate": 0.2308,
        "avg_duration_ms": 4200,
        "avg_ttfb_ms": 800,
        "avg_tps": 42.5,
        "retry_rate": 0.08,
        "switch_rate": 0.03,
        "stream_ratio": 0.9
      }
    }
  ],
  "total": { "requests": 123, "success_rate": 0.9756, "total_tokens": 3000, "...": "..." },
  "meta": { "granularity": "day", "timezone": "local", "truncated": false }
}
```

### 2.3 指标白名单

`requests` / `success` / `failed` / `interrupted` / `success_rate` / `error_rate` / `prompt_tokens` / `completion_tokens` / `cached_tokens` / `reasoning_tokens` / `total_tokens` / `cache_hit_rate` / `avg_duration_ms` / `avg_ttfb_ms` / `avg_tps` / `avg_tokens_per_request` / `retry_rate` / `switch_rate` / `stream_ratio`。

### 2.4 维度白名单

`bucket`（由 granularity 自动生成）/ `model`（`model_requested`）/ `provider` / `protocol` / `endpoint` / `account_uid` / `status` / `error_kind` / `stream` / `thinking_effort` / `tool_mode` / `client_agent`。

### 2.5 筛选白名单

`time_from` / `time_to` / `model` / `provider` / `protocol` / `endpoint` / `account_uid` / `status` / `error_kind` / `stream` / `thinking_effort` / `tool_mode` / `client_agent` / `is_probe`。

### 2.6 facets

复用数据底座的 `GET /v1/logs/facets`；统计页筛选下拉与日志页同源，避免两套 distinct 逻辑。

### 2.7 SQL 与性能

- 全部查询走 `requests` 表；`started_at` 范围过滤 + 索引。
- 聚合 SQL 用 `SUM(CASE WHEN ...)`；平均值用 `AVG(CASE WHEN ... IS NOT NULL THEN ... END)`。
- `cache_hit_rate` 等派生指标在 Python 层按 `total` 行计算，避免 SQL 除零分支。
- 首版不做预聚合表；本地 10 万行量级 `GROUP BY` 足够。若后续日志量增大，再加 `stats_hourly`/`stats_daily` 汇总表（扩展点）。
- 查询超时/大结果：`limit` 上限 500；`meta.truncated=true` 时前端提示缩小范围。

### 3.7 钻取

当前前端无 vue-router（`Shell.vue` 用 `store.view` 切页）。钻取方案：

- 在 `frontend/src/store.ts` 的 runtime store 增加 `logsPreset`（一次性筛选对象）：
  ```ts
  logsPreset: null as null | {
    timeFrom?: string; timeTo?: string;
    provider?: string; model?: string; protocol?: string;
    status?: string; errorKind?: string; accountUid?: string;
  }
  ```
- 统计页点击图表/表格行：设置 `store.logsPreset = {...}`、`store.view = 'logs'`。
- 日志页 `onMounted` 读取 `store.logsPreset`，应用到筛选后清空（避免下次进入重复应用）。
- 时间桶点击：把 `bucket` 转换为 `time_from/time_to`（小时/天/周/月边界，本地时区）。

## 4. 已知边界

- **旧数据不进入新统计**：`requests` 表从升级后开始写；升级前日志只能在日志页事件视角查看，不强行回填。
- **成本/配额不做**：订阅账号下无稳定单请求金额；后续单独立项。
- **p50/p95 不做**：第一版只做 avg；后续可在数据底座加分位数计算或明细采样。
- **缓存命中率口径**：不同供应商 prompt_tokens 是否含 cached 不同；统一按 `cached/(prompt+cached)`，UI tooltip 注明。
- **多维度限制**：首版最多 2 个业务维度 + 时间桶，避免图表不可读；更多维度后续按需放开。
- **`interrupted` 口径**：计入 requests 总数，但不计成功；成功率会体现异常退出影响。
- **性能**：本地 SQLite 10 万行量级可接受；若后续日志量增大，再加小时/天预聚合表。
- **时区**：存储 UTC，展示/分桶按本机时区；与日志页一致。
- **探针**：默认 `is_probe=false`；用户可显式包含。

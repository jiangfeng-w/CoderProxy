# 思考强度控制与日志

> 状态：已实现（2026-09-06；自动测试 158 项绿，打包安装后手工验收通过——kimi-k3 关思考正常未降级、透传/默认值/日志展示均符合预期；glm-5.3 关思考因服务端配额待补验，见已知边界）
> 优先级：核心
> 来源：模型页「默认思考强度」需求（2026-09-06 用户拍板）+ agent 思考信号形态调研（ZCode/codex/Qwen 系/Trae/opencode 实测与文档）+ 日志观测需求（用户提议，同批落地）
> 定稿日期：2026-09-06

## 1. 背景与目标

牛码目录的模型大多带思考能力（`completionOptions.thinkingEnabled` + `thinkingLevels`），但 agent 侧「关思考」的信号形态不统一：

| agent 形态 | 信号 | relay 识别 |
|---|---|---|
| ZCode（GLM 系） | `thinking: {"type":"disabled"}` | 显式关 |
| codex | `reasoning_effort: "none"` | 显式关 |
| Qwen/阿里系客户端 | `enable_thinking: false` | 显式关 |
| Trae / opencode 缺省 / 多数自定义供应商 | 不传任何思考字段 | 无法区分「没这概念」与「关了」 |

同时 relay 此前存在两个真实漏洞：

1. agent 显式传 `thinking: false` 时 ta3.py 什么都不发 → 落上游默认（大概率开思考），「关」语义丢失；
2. `enable_thinking` 字段完全不解析 → Qwen 系客户端的开关被当「没传」。

### 目标

| # | 功能 | 说明 |
|---|---|---|
| F1 | 模型列表暴露思考能力 | `/v1/models` 返回 `reasoning_efforts`（上游 thinkingLevels 的 level）+ `reasoning_labels`（中文标签）+ `supports_reasoning`；GUI 模型页展示 |
| F2 | 每模型默认思考强度 | agent 不传思考参数时按 relay 侧配置下发；GUI 模型页下拉（关 + 上游目录档位 + 目录外标准档补全） |
| F3 | 兜底策略开关（真关/假关） | ~~`thinking_unset_mode`：`default`（假关，按 F2 默认值）/ `off`（真关，一律关思考）~~ **2026-10-11 作废改道**：该预留从未在聊天路径接线（死代码），已随 [思考强度透传档位](../思考强度透传档位/思考强度透传档位.md) 移除——兜底语义由「透传（默认，不兜底）+ 每模型强制档」取代 |
| F4 | agent 信号归一 | `thinking:false/disabled` 归一为 `effort=none`（真发 `thinking:disabled`）；解析 `enable_thinking`；kimi 关思考显式发 disabled（ta3.py 本地修订） |
| F5 | 日志记录思考态 | `chat_request` 日志 detail 记录 `thinking`/`thinking_effort`（最终下发值），GUI 日志页请求行展示 |
| F6 | 非法档位透传 | agent 显式传的 `reasoning_effort` 不做档位校验/改写，原样透传上游（2026-09-06 用户拍板；曾实现「回退最低档」后否决回滚） |

### 非目标

- 不做思考预算（budget_tokens）的 GUI 配置（ta3.py 按 max_tokens 80% 自动算）。
- 不做 agent 侧协议协商（如按 agent 类型自动识别）——信号归一已覆盖已知形态。

## 2. 设计方案

### 2.1 数据源（关键决策）

思考档位**只信上游目录** `completionOptions.thinkingLevels`（牛码官方配置，各模型档位不同：glm-5.3=low/high/max、deepseek-v4=high/max），**不用任何静态目录表**（参考实现的内置目录数据源不可靠，已弃用）。上下文窗口同理走上游 `contextLength`。

### 2.2 下发语义（chat 链路）

```
agent 传了 thinking / enable_thinking / reasoning_effort 任一
  → 尊重 agent（显式关归一为 effort=none 真发 disabled）；
    reasoning_effort 即使不在该模型上游档位内也透传（F6），档位合法性由上游网关处理
都没传
  → thinking_unset_mode=off（真关）：一律 effort=none
  → thinking_unset_mode=default（假关，默认）：按 thinking_defaults[model]（缺省=none）
```

- relay 侧「关」= `thinking=True + reasoning_effort="none"` → ta3.py 发 `thinking:{"type":"disabled"}`（kimi 也显式发，本地修订对齐牛码官方 anthropicAdapter）。
- `thinking_defaults` / `thinking_unset_mode` 均走 `/v1/auth/config` 读写 + storage 持久化（非法值 400 不落盘 / 损坏回退默认）。
- F6 透传决策：各家 agent 档位命名不统一（WorkBuddy 五档 低/中/高/超高/极致 vs kimi-k3 三档 low/high/max），relay 不做「合法档位校验+回退」——用户拍板透传，让上游网关决定如何处理未知档位（宽容忽略或报错），relay 保持「不擅自改写 agent 意图」的原则。
- 实证（2026-09-06，WorkBuddy + deepseek-v4-flash-vision-exp）：该模型目录 `thinkingLevels` 仅列 high/max，agent 传 `low` 上游正常接受并返回简短思考。说明 **thinkingLevels 是官方客户端 UI 选项集，不是网关白名单**——网关接受的档位集合更大，relay 侧校验反而会把服务端本来能接受的请求改坏。
- 基于上述实证，模型页下拉在目录档位外**补全标准档** `minimal/low/medium/high/xhigh/max`。依据为国产厂商官方文档（2026-09-06 调研）：智谱 GLM-5.2+ 官方枚举即此全集（none/minimal=放弃思考，low/medium→high，xhigh→max；GLM-5.3 仅认 low/high/max），DeepSeek V4=high/max，Kimi K3=low/high/max（默认 max）。目录外档位标签标「目录外」，完整说明放在**每选项 hover tooltip**（含档位强度语义；目录档位提示「保证生效」，目录外提示「不保证生效」）；日志标签回退标准中文名（`中（medium）`）。relay 对显式档位零干预（纯透传，无归一映射）。

### 2.3 日志观测

`chat_request` 落库 detail 增加 `thinking`（bool|null）与 `thinking_effort`（str|null）——记录的是**最终下发值**（agent 显式传参或 relay 兜底之后），验收/排查时可直接核对「这次请求开了没、用的哪档」。GUI 日志页请求行追加「· 思考关 / 思考 低（low）」（有上游中文标签时双写，无标签显示原值）；旧日志无字段不展示。模型页下拉选项同样「低（low）」双写，便于对照 agent 配置值。

### 2.4 被否决的备选

- **纯 agent 为准（无 relay 默认）**：Trae 等不传参 agent 永远用不了思考，否。
- **静态目录表兜底档位**：数据源不可靠（实测 glm-5.3 上下文都标错），否。
- **思考字段建独立日志列**：低频查询字段，detail 兜底足够，不建列（对齐 M6 约定）。
- **非法档位回退到最低档**（F6 初版曾实现后回滚）：对齐官方客户端（未知档位→low），但用户拍板「不擅自改写 agent 意图」，改为透传；上游报错时由日志直观暴露，不在 relay 侧兜底掩盖。

## 3. 已知边界

- agent「不传」与「关了所以不传」协议上无法区分——靠真关/假关开关把语义选择权交给用户（M10 §7）。
- anthropic 协议模型（kimi）的「关」依赖 ta3.py 本地修订（显式 disabled），与牛码官方行为一致但未做全模型实测。
- F6 透传下，agent 传了模型不支持的档位时行为取决于上游网关（可能静默忽略或 400）；日志记录了透传的原值，可据此定位。
- **厂商侧「关」语义差异**（2026-09-06 调研，2026-10-11 联网核实补全）：GLM 系——GLM-5.2 及以下支持 `thinking.type=disabled`（传 none/minimal 放弃思考），**GLM-5.3/5.3-FLASH/GLM-4.7/GLM-4.5V 强制思考不能关**；DeepSeek 官方有 `thinking:{type:"enabled/disabled"}` 开关（anthropic 格式 `reasoning.effort:"none"`）；Kimi 官方文档——k2.6 可 `disabled`，**kimi-k3 官方 API 始终思考**（无 thinking 参数，官方客户端「关」=路由到无思考版本），k2.7-code 仅认 enabled；混元 Hy3 官方有 `enable_thinking` 快慢思考开关（WB 网关形状未验证）。**实测进展（同日，小号）**：kimi-k3 关思考正常、响应无推理内容且**未降级**（日志页核对）✅。
- **glm-5.3 关思考补验（2026-10-11，WB 上游，`../思考强度透传档位/探针-wb-glm53flash-关思考.py`，小号固定 4 请求）**：**关不掉，任何形状都关不掉**——`reasoning_effort:"none"`（现行关形状）/ `thinking:{type:"disabled"}` / `reasoning_effort:"minimal"` 均 200 且仍出思考流（基线默认思考，判定法有效）。与调研一致：GLM-5.3 系仅认 low/high/max，none/disabled/minimal 全被忽略落回默认思考；WB 网关不报 400（与智谱直连报错不同）、也不映射 low，静默忽略。**拍板（2026-10-11，上网核实后选方案 2「维持现状 + 前端标注」）**：官方文档确认 GLM-5.3/5.3-FLASH 强制思考不可关闭（z.ai docs："use forced thinking and cannot be disabled"，官方博客 "Disabling thinking is no longer supported by GLM-5.3"；直连报 400/1210「请使用 low、high 或 max」，与探针互证）；relay 下发不改，模型下拉「关」选项对 glm-5.3 系标「· 上游不支持」、tooltip 更新为实测结论，日志页「思考关」追加「（上游不支持，仍思考）」；方案 1（关→enabled+low 映射，对齐智谱 Coding Plan 网关语义）备选未采用，详见 思考强度透传档位 spec §5-8。牛码侧同模型仍无法实测（主号封禁），按调研推断同样关不掉。

## 4. 验收

1. `/v1/models` 返回 `reasoning_efforts`/`reasoning_labels`/`supports_reasoning`，与上游目录一致（glm-5.3=低/高/极）。
2. 模型页下拉改档 → 重启后保持；agent 不传参时日志显示对应档位（或关）。
3. agent 显式传 `thinking:false` / `enable_thinking:false` / `reasoning_effort:none` → 日志显示「思考关」，响应无推理内容。
4. agent 显式传 `reasoning_effort:high` → 日志显示「思考 high」，响应含推理内容。
5. 日志页请求行正确展示思考态；旧日志（无字段）不报错不展示。
6. agent 传该模型不支持的档位（如对 kimi-k3 传 `reasoning_effort: "medium"`）→ 透传上游，日志显示「思考 medium」；上游接受/拒绝均属预期。
7. relay 全量测试通过；前端 build 通过。
